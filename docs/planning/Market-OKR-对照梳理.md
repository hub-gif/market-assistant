# Market 核心 OKR 对照梳理

> **文档用途**：将 Market 核心 OKR 思维导图与 **Market-Assistant** 仓库现状逐条对照，便于汇报、排期与拆任务。  
> **对照基准**：本仓库代码与 `docs/Market-Assistant-项目进展与里程碑.md`（截至 2026-05）。  
> **重要说明**：OKR 文案以 **Amazon 一期** 为主战场表述；本仓库已深度落地的是 **京东商城**。下表用「京东已实现 / 未实现」如实标注，不与 OKR 措辞强行等同。

---

## 阅读指引

| 符号 | 含义 |
|------|------|
| ✅ 已完成 | 主路径可用，可演示 |
| 🟡 部分完成 | 有能力或脚本，未产品化/未闭环 |
| ❌ 未完成 | 仓库基本无对应模块 |
| 📎 | 仓库内主要落点（路径或模块名） |

**完成度三档**：已完成 / 部分完成 / 未完成。

---

## 一、核心目标

**OKR 表述**：用数据模块支撑 **选品、市调、竞品分析、定价分析、产品分析、品牌运营、内容管理、市场营销**。

| 方向 | 完成度 | 说明 |
|------|--------|------|
| 数据模块底座 | 🟡 | Django 任务、CSV 入库、库内浏览、run_dir 产物规范 📎 `backend/pipeline/` |
| 八大业务产品化 | 🟡 不均衡 | **竞品 + 策略（京东）** 最完整；定价 / 市调 / 营销系统等多数未独立成模块 |

---

## 二、选品

**OKR 总目标**：实现选品端到端功能模块——**数据采集、展示、分析、决策支持**。

### 2.1 分项对照

| OKR 要求 | 完成度 | 现状 | 主要落点 |
|----------|--------|------|----------|
| 数据采集 | 🟡 | 京东全自动 + 半自动可用；无 Amazon；淘系仅脚本 | 📎 `jd_keyword_pipeline`、`semiauto_tasks`、`playwright_listen` |
| 展示 | 🟡 | 任务列表、库内浏览；无「选品池」专页 | 📎 `JdResultsView`、`JdDatasetBrowseView` |
| 分析 | 🟡 | 依赖竞品报告 / brief，无选品评分模型 | 📎 `competitor_report/jd_report.py`、`build_competitor_brief_for_job` |
| 决策支持 | ❌ | 无「进池 / 不进池」规则或系统结论 | — |
| 节点：区分平台与市场 | 🟡 | `PipelineJob.platform`、按关键词分 run_dir | 📎 `models.PipelineJob` |
| 节点：打通 Amazon | ❌ | 仅测试 demo 访问 amazon.com | 📎 `tests/sb_uc_network_listener_demo.py` |
| 节点：推广到平台 2 | ❌ | 淘系前端占位，未接入任务 / 入库 / 报告 | 📎 `TbPlaceholderView`、`tb_pc_search/` |

### 2.2 小结与建议任务

**小结**：具备「京东采数 + 看数 + 竞品报告」；**不具备** OKR 意义上的选品决策模块与 Amazon / 平台 2。

| 序号 | 建议任务 | 产出 |
|------|----------|------|
| S1 | 与业务对齐选品字段与进池规则 | 打分表 / 规则说明 |
| S2 | 基于合并表 + brief 增加选品评分 API + 列表页 | 可勾选进池 |
| S3 | 淘系接入工作台（任务 → 入库 → 报告骨架） | 平台 2 MVP |
| S4 | Amazon 调研与 PoC | 单独立项文档 |

## 三、市调（进不进池）

**OKR 总目标**：跑通市调全流程；扩展类目与平台；**流程可计划执行**；**Web 功能**。

### 3.1 分项对照

| OKR 要求 | 完成度 | 现状 | 主要落点 |
|----------|--------|------|----------|
| 一期：Amazon 某品类全流程 | ❌ | 无 Amazon 采集与报告 | — |
| 扩展不同类目 | 🟡 | 更换关键词即可；无类目库管理 | 任务 `keyword` |
| 扩展不同平台 | ❌ | 除京东外未闭环 | — |
| 流程转可计划执行 | ❌ | 仅手动触发；无定时 / 周期任务 | 工程债见 📎 `docs/engineering-notes.md` |
| 开发 Web 功能 | 🟡 | 京东采集 / 任务 / 数据 / 报告 Web 已有；无「市调 / 进池」专页 | 📎 `JdSemiAutoView` 等 |

### 3.2 小结与建议任务

**小结**：京东侧已有市调**原材料**（数据 + 报告）；缺 **进不进池产品定义**、**Amazon**、**调度**、**市调专页**。

| 序号 | 建议任务 | 产出 |
|------|----------|------|
| M1 | 对齐市调输入输出（是否 = 竞品报告 + 进池表） | 一页纸流程 |
| M2 | 定时任务（关键词列表 + cron / Celery） | 可周期跑批 |
| M3 | 市调批次模型（同品类多次对比） | 批次 ID + 对比视图 |
| M4 | 进池结论页（规则或人工确认） | Web + 入库字段 |
| M5 | Amazon PoC | 独立里程碑 |

## 四、竞品分析（跟谁、打什么差异）

**OKR 总目标**：竞品分析端到端——**采集、展示、分析、决策支持**。

### 4.1 分项对照

| OKR 要求 | 完成度 | 现状 | 主要落点 |
|----------|--------|------|----------|
| 数据采集（京东） | ✅ | 全自动流水线 + 半自动 Playwright 监听 | 📎 `jd_keyword_pipeline`、`run_listen_playwright` |
| 配料 / 成分 | 🟡 | **全自动**：商详长图 + 多模态 LLM；**半自动**：占位图 URL，合并表常空 | 📎 `ingredients_op`、`semiauto_detail_ingredients.py` |
| 展示 | ✅ | 库内浏览、报告预览、简报 ZIP | 📎 `JdDatasetBrowseView`、`JdAnalysisView` |
| 分析（报告） | ✅ | 矩阵、价带、促销、评论 LLM、结构化 brief | 📎 `competitor_report/jd_report.py` |
| 「跟谁、差异」决策 | 🟡 | 策略 §5 竞争应对；报告偏描述 | 📎 `generate_strategy.py`、`strategy_draft.py` |
| Amazon 全流程 | ❌ | — | — |
| 扩平台 + 定时 + Web | 🟡 | Web（京东）✅；定时 ❌；多平台 ❌ | 见 semiauto / tasks |

### 4.2 京东半自动链路（便于汇报）

```
前端创建任务 → semiauto_tasks 后台线程
  → Playwright 监听落盘 list/detail/comment JSON
  → postprocess_semiauto_capture_json_dirs（去重 + 配料 LLM）
  → run_parse_semiauto_to_csv（四类 CSV）
  → try_ingest_job_full（入库）
```

**配料 LLM 调用点**：仅盘后 `postprocess_semiauto_capture_json_dirs` → `recognize_detail_ingredients_with_urls_joined` → `pipeline.openai_gateway.ingredients_op`。**监听阶段不调 LLM**。

### 4.3 小结与建议任务

**小结**：**京东竞品分析 MVP 基本达到 OKR「一期 Web + 全流程」**（不含 Amazon）。短板：半自动配料、定时任务、多平台、脱敏演示素材。

| 序号 | 建议任务 | 产出 |
|------|----------|------|
| C1 | 半自动从 ware JSON 抽取真实详情长图 URL，替换占位图 | 合并表「配料表」可用 |
| C2 | 定时竞品任务 + 失败通知 | 对应 OKR「可计划执行」 |
| C3 | 报告固定输出「对标建议表」（跟谁、差异） | 决策支持增强 |
| C4 | 阶段 1.4：脱敏截图 / 录屏 | 可对外演示 |
| C5 | Amazon 或淘系二选一立项 | 路线图 |

## 五、定价分析（卖什么价、活动边界）

**OKR 总目标**：定价与毛利权衡模块；成本 / 费用拆解 → **价格区间与毛利试算表**（立项、上架、调价）。

### 5.1 分项对照

| OKR 要求 | 完成度 | 现状 | 主要落点 |
|----------|--------|------|----------|
| 成本与费用拆解表 | ❌ | 无独立数据模型或标准模板 | — |
| 可选输入：成本、佣金、运费、广告占比 | ❌ | 无试算表单页 | — |
| 一键计算毛利、底价 | ❌ | — | — |
| 立项 / 上架 / 调价场景试算表 | ❌ | — | — |
| 竞品侧价格监测 | 🟡 | 合并表、报告价带与促销信号（非本品成本） | 📎 `jd_report` 价盘章节、`generate_group_summaries` |

### 5.2 小结与建议任务

**小结**：本条 OKR **几乎未做**；仅有竞品**监测价**与策略文案中的定价建议，不是「成本 + 费用 → 毛利试算」产品。

| 序号 | 建议任务 | 产出 |
|------|----------|------|
| P1 | 与财务 / 运营对齐试算表字段 | 字段说明 |
| P2 | 后端试算 API（纯公式） | `PricingTrial` 或等价模块 |
| P3 | 前端单页：输入 → 毛利 / 底价 / 区间 | 可导出 Excel |
| P4 | 可选：从合并表拉竞品到手价作对标列 | 与监测数据联动 |

## 六、产品分析（做不做、规格与交期）

**OKR 总目标**：多维度数据呈现与对比。

### 6.1 各维度对照

| 维度 | 完成度 | 现状 | 主要落点 |
|------|--------|------|----------|
| 品牌 | 🟡 | 合并表、报告品牌分布与集中度；无独立品牌专题页 | 📎 `jd_report` 竞争结构 |
| 功效 | 🟡 | 词云 / 矩阵归纳；无标准功效词表 | 报告 LLM 章节 |
| **成分（配料）** | 🟡 | 全自动 LLM ✅；半自动占位图 ❌ | 📎 `ingredients_op`、`semiauto_detail_ingredients.py` |
| 价格 | ✅ | 价带、标价、到手价、促销拆解 | 合并表 + 报告第六章 |
| 市场份额 | 🟡 | 渠道内店铺 / 品牌 CR；**非**全渠道市占；可配外部市场表 | 📎 brief、`EXTERNAL_MARKET_TABLE_ROWS` |
| 痛点 | ✅ | 评论 flat、报告 §8.3、策略 §2.1 证据链 | 📎 `jd_item_comment_parse` |
| 技术路线 | ❌ | 无剂型 / 工艺 / 专利等字段 | — |
| 渠道经销商 | 🟡 | 店铺名与集中度；无经销商体系 | 列表 / 商详店铺字段 |

### 6.2 小结与建议任务

**小结**：品牌、价格、评论痛点、（全自动）成分有数据；功效结构化、真市占、技术路线、经销商、半自动成分缺口大；**无独立「产品分析」菜单**。

| 序号 | 建议任务 | 产出 |
|------|----------|------|
| A1 | 半自动成分接真图（与竞品 C1 同项） | 成分列覆盖率提升 |
| A2 | 「产品分析」固定页（维度表 / 雷达） | 从 brief + 合并表生成 |
| A3 | 功效 / 成分词表（品类级配置） | 可对比 |
| A4 | 外部市占表录入表单 | 报告展示产品化 |
| A5 | 评估从「商品参数」扩展技术路线 | 需求评审 |
